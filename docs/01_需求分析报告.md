# Puppies-Game 需求分析报告

**项目名称**: Puppies-Game（狗国建设者）
**项目类型**: 浏览器 Web 增量游戏
**更新日期**: 2026-07-01

## 1. 项目概述

Puppies-Game 是一款面向浏览器的放置/增量式经营游戏。玩家从少量狗狗和基础资源开始，通过点击采集、建造、岗位分配、科技研究、工坊升级、政策选择和离线收益，逐步建设一个可长期成长的狗狗文明。

项目采用 React 19、TypeScript 5.9、Vite 8、Zustand、Tailwind CSS 4、shadcn/radix-ui 组件体系实现。当前版本为纯前端应用，数据保存于浏览器本地存储，可通过 GitHub Pages 部署。

## 2. 项目目标

- 实现一个可运行、可保存、可持续扩展的 Web 增量游戏。
- 体现软件工程四个工作域：需求、设计、实现、演化。
- 覆盖软件过程、需求工程、系统建模、架构设计、工程化、测试质量、配置运维七个实践方向。
- 保持核心游戏逻辑与 UI 解耦，使资源、建筑、科技、工坊和政策可以继续数据化扩展。

## 3. 用户与使用场景

### 3.1 目标用户

- 喜欢 Kittens Game、Cookie Clicker 等增量游戏的玩家。
- 需要短时间操作、长时间累积反馈的休闲玩家。
- 课程项目评审者，用于检查项目完整度、工程化实践和测试质量。

### 3.2 主要场景

- 玩家打开页面，加载本地存档并进行离线收益结算。
- 玩家通过点击和自动生产积累资源。
- 玩家购买建筑，提高资源产出、资源上限或人口上限。
- 玩家给狗狗分配岗位，平衡食物、木材、科学、文化、黄金等资源。
- 玩家研究科技、解锁工坊项目、制定政策，推动中后期成长。
- 玩家保存、读取或重置存档。

## 5. 非功能需求

### 5.1 性能需求

| ID | 指标 | 目标 |
| --- | --- | --- |
| NF-01 | 页面启动 | 普通桌面浏览器中快速加载，生产构建可静态托管 |
| NF-02 | tick 性能 | 5 tick/s 下保持 UI 可交互 |
| NF-03 | 离线结算 | 离线模拟上限为 8 小时，避免加载时长失控 |
| NF-04 | 构建体积 | 使用 Vite 生产构建，输出静态资源 |

### 5.2 可维护性需求

| ID | 需求 | 实施方式 |
| --- | --- | --- |
| NF-05 | 类型安全 | TypeScript 严格类型和领域类型定义 |
| NF-06 | 逻辑可测试 | 核心规则集中在 `src/engine/`，脱离 React 测试 |
| NF-07 | 内容可扩展 | 资源、建筑、科技、工坊、政策集中定义在 `src/engine/types.ts` |
| NF-08 | 状态可追踪 | Zustand store 作为 UI 与引擎之间的适配层 |
| NF-09 | 代码规范 | ESLint、Prettier、TypeScript 构建校验 |

### 5.3 可靠性需求

| ID | 需求 | 实施方式 |
| --- | --- | --- |
| NF-10 | 存档可靠 | 存档加载、保存、重置具备单元测试 |
| NF-11 | 资源不越界 | tick 后按资源上限截断 |
| NF-12 | 人口状态一致 | 人口、岗位、领袖狗删除时同步修正 |
| NF-13 | 功能回归可控 | CI 执行 lint、单元测试、覆盖率和构建 |

## 6. 约束与假设

- 当前项目为单机浏览器游戏，不包含账号、服务器、多人同步和数据库。
- 存档依赖浏览器 localStorage，清除站点数据会删除进度。
- 美术资源以轻量 UI、图标和文字为主，优先保证玩法闭环与工程质量。
- 课程提交文档以 Markdown 编写，可按要求导出 PDF。

## 7. 验收标准

- `npm install` 后可运行开发、测试和构建命令。
- `npm run lint`、`npm run test:run`、`npm run build` 均通过。
- 玩家可完成从基础采集到建筑、岗位、科技、工坊、政策的核心流程。
- 关闭页面后再次打开能够读取存档并结算离线收益。
