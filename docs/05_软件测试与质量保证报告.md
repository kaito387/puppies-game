# Puppies-Game 软件测试与质量保证报告

**项目名称**: Puppies-Game（狗国建设者）
**更新日期**: 2026-07-01

## 1. 测试目标

测试工作的目标是保证 Puppies-Game 的核心规则稳定、存档可靠、UI 操作不会破坏游戏状态，并在项目演化时及时发现回归问题。

重点质量目标：

- 游戏 tick 在资源、人口、建筑、科技、政策叠加时保持一致。
- 玩家购买、研究、解锁、制定政策等操作具备正确的前置校验。
- 存档、读取、重置、离线收益能够稳定工作。
- 工程命令 `lint`、`test`、`build` 可以作为交付前准入门槛。

## 3. 测试策略

### 3.1 以 engine 为核心

游戏规则集中在纯 TypeScript 模块中，测试优先覆盖 engine 层。这样可以避免 UI 测试不稳定，同时快速验证资源、人口、建筑、科技、政策等核心逻辑。

### 3.2 回归测试优先

每次修改游戏规则时，必须考虑是否会影响：

- 资源是否会超过上限。
- 建筑成本和购买条件是否正确。
- 科技/工坊/政策前置是否仍然有效。
- 人口增长、饥荒死亡、岗位经验是否一致。
- 离线收益是否与在线 tick 行为一致。

### 3.3 自动化准入

合并前建议执行：

```bash
npm run lint
npm run test:run
npm run build
```

CI 中还会执行：

```bash
npm run test:coverage
```

## 5. 缺陷跟踪方法

课程项目中建议使用 GitHub Issues 或 PR 描述记录缺陷：

| 字段 | 说明 |
| --- | --- |
| 标题 | 简短描述问题 |
| 环境 | 浏览器、系统、分支、commit |
| 复现步骤 | 从初始状态到触发问题的步骤 |
| 实际结果 | 当前错误行为 |
| 预期结果 | 正确行为 |
| 严重级别 | P0/P1/P2/P3 |
| 修复验证 | 关联测试或手动验证命令 |

严重级别建议：

- P0: 无法启动、无法构建、存档损坏。
- P1: 核心玩法错误，例如资源无限增长或购买条件失效。
- P2: 局部功能错误，例如某个政策效果不正确。
- P3: 文案、布局、易用性问题。

## 6. 质量保证措施

### 6.1 代码质量

- TypeScript 类型约束核心数据结构。
- ESLint 检查常见代码问题和 React Hooks 规则。
- Prettier 统一格式。
- 核心逻辑通过纯函数组织，便于测试和审查。

### 6.2 流程质量

- Pull Request 合并前运行 CI。
- 规则变更必须补充或更新测试。
- 文档与代码同步更新，避免提交材料过期。
- 使用 `simulation.ts` 对长期进度和平衡进行辅助验证。

### 6.3 交付质量

- 生产构建必须成功。
- GitHub Pages 部署来源为 `dist` 静态产物。
- 文档编号与课程 PDF 提交清单一致。
- 补充设计资料放在 10 及以后编号，避免交付件混淆。
