# Puppies-Game 软件配置与运维文档

**项目名称**: Puppies-Game（狗国建设者）
**更新日期**: 2026-07-01

## 1. 配置管理目标

本项目采用 npm、Git、GitHub Actions 和 GitHub Pages 管理配置、版本、构建和部署。目标是保证开发者能够在一致环境下安装依赖、运行测试、构建产物，并把稳定版本发布到静态站点。

## 2. 运行环境

| 类别 | 配置 |
| --- | --- |
| 运行形态 | 浏览器单页应用 |
| Node.js | CI 使用 Node 24.x |
| 包管理器 | npm |
| 构建工具 | Vite 8 |
| 语言 | TypeScript 5.9 |
| 部署目标 | GitHub Pages |
| 存储 | 浏览器 localStorage |

## 3. 本地配置

### 3.1 安装依赖

```bash
npm install
```

CI 环境使用：

```bash
npm ci
```

### 3.2 本地开发

```bash
npm run dev
```

默认由 Vite 启动开发服务器。若端口被占用，Vite 会提示可用端口。

### 3.3 生产构建与预览

```bash
npm run build
npm run preview
```

`npm run build` 会先执行 TypeScript 构建，再输出 Vite 生产产物到 `dist/`。

## 5. 版本控制

### 5.1 Git 管理策略

- 所有源码、文档、配置、测试进入 Git。
- `node_modules/`、`dist/`、`coverage/` 等生成物不应作为源码提交。
- 通过 Pull Request 进行代码审查。
- main 分支保持可构建、可部署。

### 5.2 版本标识

当前 `package.json` 版本为 `0.1.0`。建议后续采用语义化版本：

- `MAJOR`: 存档结构或玩法机制重大不兼容。
- `MINOR`: 新增建筑、科技、系统或 UI 面板。
- `PATCH`: bug 修复、文案、平衡小调整。

## 6. 持续集成

CI 触发条件：

- push 到 `main` 或 `develop`。
- pull request 到 `main` 或 `develop`。

CI 步骤：

1. checkout 仓库。
2. setup-node 24.x 并启用 npm cache。
3. `npm ci` 安装依赖。
4. `npm run lint`。
5. `npm run test:run`。
6. `npm run test:coverage`。
7. 上传覆盖率到 Codecov。
8. `npm run build`。
9. 上传 `dist` artifact。

## 7. 部署方案

### 7.1 自动部署

当 main 分支收到 push 且 build job 通过后，deploy job 执行：

- `npm ci`
- `npm run build`
- `actions/configure-pages`
- `actions/upload-pages-artifact`
- `actions/deploy-pages`

部署产物为 `dist/`，访问地址由 GitHub Pages 环境输出。`package.json` 中配置的 homepage 为：

```text
https://kaito387.github.io/puppies-game/
```

### 7.2 手动部署备用

项目保留 `gh-pages` 依赖和命令：

```bash
npm run deploy
```

该方案会把 `dist` 发布到 gh-pages 分支，可作为 Pages workflow 的备用方式。

## 8. 运维计划

### 8.1 日常检查

| 项目 | 方法 |
| --- | --- |
| 构建状态 | 查看 GitHub Actions |
| 部署状态 | 查看 GitHub Pages environment |
| 测试覆盖 | 查看 coverage 输出和 Codecov |
| 页面可访问性 | 打开 GitHub Pages URL |
| 控制台错误 | 浏览器 DevTools 检查 |

### 8.2 发布前检查

```bash
npm run lint
npm run test:run
npm run build
npm run preview
```

发布前人工检查：

- 首屏能正常加载。
- 资源面板显示正常。
- 建筑/管理/科技/工坊/政策标签页可切换。
- 保存、读取、重置可用。
- 刷新页面后存档恢复。

### 8.3 回滚策略

- 若 main 最新部署不可用，可在 GitHub 中 revert 对应 commit，再触发 CI/CD 重新部署。
- 若仅文档或非运行时代码出错，可提交修复 commit。
- 若依赖升级导致构建失败，可回退 `package.json` 和 `package-lock.json` 的相关变更。

## 9. 数据与备份

当前游戏数据保存在用户浏览器 localStorage 中：

- 优点：无需后端，部署简单。
- 风险：用户清除浏览器数据会丢失存档。
- 后续改进：增加存档导出/导入，或增加云存档服务。

## 10. 安全与权限

- 项目不处理用户密码、支付、个人身份信息。
- GitHub Pages deploy job 使用 Pages 所需权限：`contents: read`、`pages: write`、`id-token: write`。
- 不在仓库中提交密钥、token 或私有配置。
